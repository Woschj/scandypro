# VB-001 – Private Kanban-Karten nicht durchgängig geschützt (IDOR)

- **Schweregrad:** Critical
- **Priorität:** P0 – Sicherheitsfix
- **Kategorie:** Broken Access Control / Art. 9 DSGVO
- **Rollen:** Teilnehmer, Berufstrainer
- **Fundort:**
  - `app/core/access.py` – `sichtbare_karten_filter` (nur beim Rendern der
    Board-Ansicht angewendet)
  - `app/routers/kanban_karten.py` – `karte_aktualisieren`, `karte_loeschen`,
    `karte_verschieben`, `spalte_reihenfolge_setzen`,
    `zuweisung_hinzufuegen`, `zuweisung_entfernen`,
    `unteraufgabe_hinzufuegen`, `unteraufgabe_umschalten`,
    `unteraufgabe_loeschen`

## Problem

`sichtbare_karten_filter` filtert private Karten (`Karte.sichtbarkeit ==
privat`) nur in der Board-Rendering-Ansicht heraus. Die mutierenden
Endpunkte in `kanban_karten.py` prüfen ausschließlich `require_kanban_access`
(Zugriff auf das *Board*), nicht die Sichtbarkeit der *einzelnen Karte*. Ein
zuständiger Berufstrainer mit Zugriff auf das Personen-Board einer/eines
Teilnehmer:in kann daher über die (sequenzielle, erratbare) `karte_id` eine
als privat markierte Karte lesen (Formularvorbefüllung beim Bearbeiten),
ändern, löschen, verschieben oder mit Unteraufgaben/Zuweisungen versehen –
obwohl das Modell (`app/models/kanban.py:Karte`) und
`sichtbare_karten_filter` das explizit ausschließen sollen.

## Warum das ein Problem ist

- Widerspricht CLAUDE.md §17 (Broken Access Control) und §1 "Selbstbestimmung
  vor Fürsorge" – private Karten sind der einzige Ort im Kanban-Modul, an dem
  Teilnehmer:innen bewusst etwas *nicht* mit dem Trainer teilen.
- Art.-9-relevant, sobald private Karteninhalte Gesundheits-/Belastungsbezug
  haben (z. B. "Termin bei der Psychotherapeutin").
- IDs sind fortlaufend und damit erratbar – kein Secret nötig, reines
  Durchprobieren genügt.

## Lösungsvorschlag

Neue zentrale Prüffunktion in `app/core/access.py`, die dieselbe Logik wie
`sichtbare_karten_filter` für eine einzelne Karte kapselt:

```python
async def require_karte_sichtbar(current_user: User, board: Board, karte: Karte) -> None:
    if board.typ != BoardTyp.person or current_user.id == board.person_teilnehmer_id:
        return
    if karte.sichtbarkeit == KartenSichtbarkeit.team or karte.ersteller_id == current_user.id:
        return
    raise HTTPException(status.HTTP_403_FORBIDDEN, "Diese Karte ist privat und nicht für dich sichtbar.")
```

`sichtbare_karten_filter` auf dieselbe Hilfsfunktion umstellen (kein
doppelter Logikpfad). In `kanban_karten.py` nach jedem `_board_von_karte(...)`
(bzw. nach Auflösen von `unteraufgabe.karte_id`) zusätzlich
`require_karte_sichtbar(current_user, board, karte)` aufrufen. Für
`spalte_reihenfolge_setzen` (Batch über mehrere Karten): nicht sichtbare
Karten in der Schleife überspringen (`continue`) statt den ganzen Request
abzulehnen – konsistent mit dem bestehenden Verhalten bei ungültigen
Board-Zuordnungen dort.

## Aufwand

**S** – ein neuer Helper + Aufruf an 8 Stellen, keine Migration nötig.

## Abhängigkeiten

Keine.

## Abnahmekriterien

- [ ] Trainer erhält 403 beim Versuch, eine private Karte eines Personen-Boards
      über `karte_id` zu bearbeiten/löschen/verschieben/zuzuweisen
- [ ] Unteraufgaben-Endpunkte respektieren dieselbe Prüfung
- [ ] `spalte_reihenfolge_setzen` überspringt fremde private Karten statt
      zu fehlschlagen
- [ ] Owner (Teilnehmer:in) und Team-Karten bleiben unverändert nutzbar
- [ ] `sichtbare_karten_filter` nutzt denselben Helper (keine Logikduplizierung)
