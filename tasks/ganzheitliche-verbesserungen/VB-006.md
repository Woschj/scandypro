# VB-006 – Mein-Tag-Minispiel-Pool auf ≥10 Übungen erweitern

- **Schweregrad:** High
- **Priorität:** P1
- **Kategorie:** Feature / Mental-Health-UX
- **Rollen:** Teilnehmer
- **Fundort:** `app/core/atemuebungen.py`, `app/models/wohlbefinden.py`,
  `app/static/js/tagebuch-interaktiv.js`,
  `app/templates/wohlbefinden/teilnehmer_ansicht.html`

## Ausgangslage

Aktuell gibt es genau zwei interaktive Elemente im 5-Minuten-Tagebuch:
Atemübung (morgens, 15 stilistische Varianten desselben Übungstyps
"Verbinde-die-Punkte") und Zeichnung (abends, freie Zeichenfläche). Beide
folgen demselben guten Grundprinzip: **kein Scoring, kein Richtig/Falsch,
nur Teilnahme**; nur der Abschluss-Zeitpunkt (bzw. bei der Zeichnung das
Bild selbst) wird gespeichert, nicht der "Erfolg". Die Auswahl der
Atemübungs-*Variante* erfolgt deterministisch über einen Hash aus
Teilnehmer-ID + Datum (`_tages_index` in `atemuebungen.py`) – das
garantiert aber nur Stabilität pro Tag, keine Verteilung über eine Woche:
zwei Tage hintereinander (oder eine ganze Woche) können zufällig dieselbe
Übung zeigen.

Ziel dieses Punkts: den Pool an *Übungstypen* (nicht nur Stil-Varianten)
auf mindestens 10 erweitern und die Auswahl so ändern, dass innerhalb einer
Arbeitswoche (Mo–Fr) keine Wiederholung auftritt.

## Architektur-Änderung: Wochen-Rotation statt Tages-Hash

Neue Funktion in `app/core/tagesuebungen.py` (neu, ersetzt/ergänzt
`atemuebungen.py` als Spezialfall):

```python
def uebung_der_woche_index(teilnehmer_id: int, datum: date, anzahl: int) -> int:
    """Deterministische, pro Kalenderwoche neu gemischte Reihenfolge.
    Fisher-Yates mit Seed aus (teilnehmer_id, ISO-Jahr, ISO-Woche) - alle
    Werte 0..anzahl-1 kommen innerhalb einer Woche genau einmal vor
    (bei anzahl >= 5 also nie zwei gleiche Werte Mo-Fr), Sa/So nutzen
    den nächsten Index zyklisch weiter."""
```

Der Pool wächst von 2 auf ≥12 Einträge (2 bestehende + mindestens 10 neue),
wodurch selbst bei Poolgröße 12 im Schnitt erst nach über zwei Wochen ein
Übungstyp wieder auftaucht. Bestehende `atemuebung_name`/
`atemuebung_erledigt_am`-Felder bleiben für Bestandsdaten/Rückwärts-
kompatibilität erhalten; neue generische Felder auf `TagebuchEintrag`:

```python
tagesuebung_typ: str | None = None            # z.B. "Grounding", "Koerperscan", ...
tagesuebung_erledigt_am: datetime | None = None
tagesuebung_ergebnis: str | None = Field(default=None, sa_column=Column(VerschluesselterText))  # nur wo inhaltlich sinnvoll (z.B. Stärken-Karte-Antwort), sonst None
```

Migration: additive (3 neue nullable Spalten), kein Datenverlust.

## Neue Übungstypen (mindestens 10, zusätzlich zu Atemübung + Zeichnung)

| # | Name | Technik-Hintergrund | Tageszeit | Speichert Inhalt? | Aufwand |
|---|---|---|---|---|---|
| 1 | **5-4-3-2-1-Erdung** | Sensorisches Grounding gegen Anspannung | morgens | nein (nur Abschluss) | einfach |
| 2 | **Gedanken-Waage** | CBT-light: belastender Gedanke + ausgewogenere Sicht daneben | abends | optional (Ergebnisfeld) | einfach |
| 3 | **Sorgen loslassen** | Expressive-Writing: Sorge eintippen, als "Ballon" wegwischen | abends | **nein, bewusst nicht gespeichert** – Loslassen ist der Zweck | einfach |
| 4 | **Ein Wort für heute** | Emotionale Granularität statt Skala: Klick auf 1 von ~20 sanften Wörtern | morgens/abends | ja (gewähltes Wort) | einfach |
| 5 | **Körper-Scan light** | Progressive Muskelentspannung: SVG-Körperzonen mit Halten-Timer antippen | abends | nein (nur Abschluss) | mittel |
| 6 | **Ruhe-Ort-Visualisierung** | Sicherer-Ort-Anker: 3 kurze Freitextfelder (sehen/hören/spüren) | abends | ja (3 Kurztexte) | einfach–mittel |
| 7 | **Ausmal-Mandala** | Alternative zur freien Zeichnung ohne Leistungsdruck | abends | ja (wie Zeichnung, Bild-Pfad) | mittel |
| 8 | **Dankbarkeits-Foto-Moment** | Foto statt Text, niedrigschwelliger an Tagen mit wenig Energie | abends | ja (Foto, wie Zeichnung-Upload) | einfach |
| 9 | **Stärken-Karte** | Ressourcenorientierte Reflexion: Karte umdrehen, Prompt zu eigener Stärke | morgens | optional (Kurzantwort) | einfach |
| 10 | **Mini-Ziel des Tages** | Sehr kleines selbstgewähltes Ziel, abends Ja/Nein-Haken, kein Streak-Zwang | morgens+abends | ja (Zieltext + erledigt-Flag) | einfach |
| 11 | *(optional, 11. Ergänzung)* **Selbstfürsorge-Impuls** | Rein lesender, täglich rotierender Impuls ("Trink heute bewusst ein Glas Wasser mehr") nach Pool-Muster wie `tagebuch_prompts.py` | morgens | nein (nur Abschluss) | einfach |

Damit ergeben sich **12 Übungstypen insgesamt** (2 bestehende + 10
verpflichtend neue + 1 optional), ausreichend für eine vollständig
wiederholungsfreie Arbeitswoche mit Puffer für zwei Wochen.

## Umsetzungsreihenfolge (innerhalb VB-006)

1. `tagesuebungen.py` mit Wochen-Rotationslogik + Pool-Registry
   (Metadaten: Name, Tageszeit-Empfehlung, Renderer-Typ) anlegen.
2. Migration für die 3 neuen generischen Felder.
3. Pro Übungstyp: kleines Template-Partial + ggf. Alpine-Snippet,
   wiederverwendbar wo möglich (z. B. Halten-Timer-Logik aus
   `tagebuch-interaktiv.js` für Körper-Scan wiederverwenden).
4. Router-Handling (`app/routers/wohlbefinden.py`) um generisches
   Speichern von `tagesuebung_typ`/`_erledigt_am`/`_ergebnis` erweitern.
5. Bestehende Atemübung/Zeichnung unverändert lassen, nur zusätzlich in die
   Wochen-Rotation einspeisen.

## Aufwand

**L** – größtes Einzelthema der Liste, bewusst in obige Teilschritte
zerlegt; wird selbst iterativ (Typ für Typ) abgearbeitet statt in einem
Schritt.

## Abhängigkeiten

Keine zu anderen VB-Punkten; kann unabhängig von VB-001–005 laufen, wird in
der Liste aber nach den kritischeren Sicherheits-/DSGVO-Punkten eingeordnet.

## Abnahmekriterien

- [ ] Pool enthält mindestens 12 unterscheidbare Übungstypen (inkl.
      bestehender Atemübung + Zeichnung)
- [ ] Rotation garantiert: innerhalb von Mo–Fr derselben Kalenderwoche
      wird kein Übungstyp zweimal gezeigt
- [ ] Jeder neue Typ folgt dem bestehenden Prinzip: kein Scoring, keine
      wertende Sprache, positive/neutrale Formulierung (CLAUDE.md §24)
- [ ] Migration ist additiv, bestehende Einträge/Atemübungs-Historie bleibt
      unverändert lesbar
- [ ] Jeder neue Typ ist einzeln in `deletion.py`/Löschkaskade berücksichtigt
      (insbesondere Foto-Uploads bei Dankbarkeits-Foto-Moment)
