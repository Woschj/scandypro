# VB-002 – Kein "Ich brauche jetzt Unterstützung"-Button in Mein Tag

- **Schweregrad:** Critical
- **Priorität:** P0
- **Kategorie:** Sicherheit/Fürsorge (kein reines UX-Feature)
- **Rollen:** Teilnehmer
- **Fundort:** `docs/WOHLBEFINDEN_KONZEPT.md` (fordert dies als frühen
  Baustein), `app/routers/wohlbefinden.py`,
  `app/templates/wohlbefinden/teilnehmer_ansicht.html` (nicht vorhanden)

## Problem

"Mein Tag" ist ein Mental-Health-nahes Modul, das täglich mit Stimmung,
Belastung und Freitext arbeitet – aber es gibt keinen jederzeit sichtbaren,
niedrigschwelligen Weg, aktiv Unterstützung anzufordern oder auf externe
Hilfsangebote (Telefonseelsorge, PSM-Kontakt, Krisendienst) hingewiesen zu
werden. Das Konzept-Dokument nennt das explizit als frühen Baustein, im Code
fehlt er komplett.

## Warum das ein Problem ist

Bei einem Tool, das aktiv nach Belastung fragt, ohne einen Ausweg/Hilfe-Weg
anzubieten, entsteht eine Fürsorgelücke – gerade in einem Reha-Kontext mit
vulnerablen Nutzer:innen sicherheitsrelevant, nicht nur "nice to have".

## Lösungsvorschlag

Dezente, immer erreichbare Kachel/Link auf der "Mein Tag"-Seite (nicht als
rotes Warnsymbol, siehe CLAUDE.md §24) mit: (a) direkter, konfigurierbarer
Kontaktmöglichkeit zur zuständigen PSM-Person (sofern zugeordnet), (b)
statischen, immer verfügbaren externen Hilfsangeboten (Telefonseelsorge
0800-1110111 o. ä. – Einrichtung konfiguriert Text). Kein Tracking, kein
Zwang zur Angabe eines Grundes, kein automatisches Auslösen durch schlechte
Werte (keine "automatischen Eskalationen", CLAUDE.md §24) – rein
nutzerinitiiert.

## Aufwand

**M** – neue Konfigurationsfelder (Einrichtung: Hilfetext/Kontaktnummer),
ein Template-Partial, keine neue Tabelle nötig wenn statisch aus Settings.

## Abhängigkeiten

Keine zu anderen VB-Punkten.

## Abnahmekriterien

- [ ] Button/Link ist auf jeder "Mein Tag"-Unterseite sichtbar, sanft
      formuliert, kein Warnsymbol
- [ ] Zeigt zuständige PSM-Kontaktinfo (falls Zuordnung besteht) + statische
      externe Hilfsangebote
- [ ] Kein automatisches Auslösen, keine Benachrichtigung an Dritte ohne
      aktives Zutun der/des Nutzer:in
- [ ] Klick wird nicht geloggt/auditiert (kein Content-Bezug, siehe §9)
