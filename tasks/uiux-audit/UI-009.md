# UI-009 – Sticky-Topnav ohne Mobile-Kollaps

- **Schweregrad:** High
- **Priorität:** P1
- **Kategorie:** Responsive / Mobile-First-Guideline
- **Fundort:**
  - [app/templates/base.html:12-45](app/templates/base.html) (Topnav-Markup, bis zu 5 Links + Dropdown + User-Chip je nach Rolle)
  - [app/static/css/style.css:237-274](app/static/css/style.css) (`.topnav { position: sticky; ... flex-wrap: wrap; }`, kein Media Query, kein Hamburger-Menü)

## Problem

Die Topnav ist dauerhaft `position: sticky; top: 0` und nutzt bei zu
wenig Platz `flex-wrap: wrap`, um Einträge umzubrechen – es gibt jedoch
keinen Breakpoint, der auf ein kompaktes Mobile-Menü (Hamburger o. ä.)
umschaltet. Für Teilnehmer:innen sind das Wordmark + 5 Nav-Links
("Projekte", "Wochenberichte", "Mein Tag", "Bewerbungen", "Meine
Freigaben") + User-Chip mit Namen/Rolle + Abmelden-Button – auf
Mobile-Breite (375px, siehe CLAUDE.md Abschnitt 24 "Mobile First")
bricht das zwangsläufig auf mehrere Zeilen um.

## Warum das ein Problem ist

- CLAUDE.md Abschnitt 24 fordert explizit "Mobile First" mit "kurzen
  Formularen, schneller Interaktion". Eine dauerhaft sticky, 2-3-zeilige
  Navigation frisst auf einem kleinen Bildschirm einen erheblichen,
  permanent sichtbaren Anteil der Nutzhöhe – besonders schmerzhaft bei
  den ohnehin schon langen Formularen (Wochenbericht, Bewerbung anlegen).
  bereits
- Das Umbruchverhalten ist unvorhersagbar (abhängig von Namenslänge,
  Rollentext, Anzahl sichtbarer Links je Rolle) – für Berufstrainer:innen
  mit "Handlungsfeld-Team"-Link kommt ein weiterer, recht langer
  Linktext hinzu, für Admins ein zusätzliches Dropdown "Verwaltung".
- Kein erkennbares Muster für Touch-Bedienung wurde für diesen Fall
  vorgesehen (kein größerer Touch-Target-Abstand bei umgebrochenen Links).

## Erwartete Nutzerauswirkung

Mehr nutzbare Bildschirmfläche auf Mobilgeräten, vorhersagbare,
kompakte Navigation, bessere Erfüllung der eigenen Mobile-First-Vorgabe.

## Lösungsvorschlag

- Ab einem Breakpoint (z. B. `max-width: 720px`) Nav-Links hinter einem
  Hamburger-/Menü-Button einklappen (z. B. mit einem `<details>`-Element
  analog zum bereits genutzten `nav-dropdown`-Muster – konsistent mit dem
  Rest der App, ohne neues JS-Framework).
- Wordmark + Menü-Button + kompakter User-Indikator bleiben einzeilig
  sichtbar; die eigentlichen Links erscheinen in einem ausklappbaren
  Panel.
- `--nav-height` im Mobile-Fall auf einen festen, einzeiligen Wert
  begrenzen, damit UI-015 (Toast-Position) automatisch mitgelöst wird.

## Aufwand

**M** – ein neuer Breakpoint plus Markup-Anpassung in `base.html`,
wiederverwendet das bestehende `<details>`-Dropdown-Pattern.

## Abhängigkeiten

Löst UI-015 (Toast-Positionierung) als Nebeneffekt mit, da beide auf
derselben Ursache (variable Nav-Höhe) beruhen. Sollte vor UI-015
umgesetzt werden.

## Abnahmekriterien

- [ ] Bei 375px Breite bleibt die Topnav einzeilig
- [ ] Alle Nav-Links bleiben über einen klar erkennbaren Menü-Button
      erreichbar
- [ ] Getestet für alle vier Rollen (unterschiedliche Linkmengen)
- [ ] Kein horizontales Scrollen/Clipping der Nav bei 320-375px
